# ADR 0007: Сигналы группировки связанных сообщений

* **Статус:** принято
* **Дата:** 2026-11-16
* **Основание:** ТЗ §9, §4.4

## Контекст

Нужно определять, какие сообщения составляют один материал. ТЗ требует разделять
технические дубли, повторные пересылки, ответы в обсуждении, альбомы и просто
близкие по времени сообщения, и запрещает объединять по времени или «похожести».

## Решение

Учитываются только достоверные сигналы, доступные в конкретном источнике:

| Сигнал | Доступность | Правило |
|---|---|---|
| `joined` | HTML | подряд идущие сообщения одного блока автора → одна группа, максимум 10 |
| `reply_to_id` | HTML | пара «оригинал + ответ», если оба есть в экспорте и не заняты другой группой |
| `media_group_id` | только Bot API | в HTML отсутствует; сигнал помечен как недоступный |
| близость по времени | всегда | **не используется** |
| общий автор | всегда | **не используется** |

Группы — только **кандидаты**: они публикуются как предложения в
`Review/<kb_id>/<proposal_id>.md` и никогда не применяются автоматически
(ТЗ §4.4, §9.2). Размер группы ограничен, группы не пересекаются.

## Последствия

* На текущем экспорте найдено 113 групп `joined_run` и 116 пар `reply_chain`
  → 229 предложений в `Review/`.
* Ответы могут быть самостоятельными материалами — поэтому это предложение,
  а не слияние; решение принимает пользователь.
* Альбомы станут доступны только на live-приёме (Bot API), и их обработка
  потребует окна ожидания (у альбома нет события «завершён»).
* Команда `kbcollector groups` идемпотентна: повторный запуск не создаёт дублей.

## Проверка

`tests/unit/test_grouping.py`: продолжения, ответы, отсутствие группировки по времени,
непересекаемость, ограничение размера, стабильность `proposal_id`, текст предложения.
